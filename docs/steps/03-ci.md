# Step 03 — CI con GitHub Actions

**Etapa:** 1. Base · **Depende de:** 01 · **Leer:** `AGENTS.md` sección "Git y PR"

## Objetivo

Que cada PR ejecute automáticamente lint, chequeo de tipos, tests y build, y que no se pueda mergear si algo falla.

## Tareas

- [ ] `.github/workflows/ci.yml` que corra en `pull_request` hacia `main` y en `push` a `main`.
- [ ] Pasos: checkout, `pnpm/action-setup`, `actions/setup-node` con la versión de `.nvmrc` y caché de pnpm, `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
- [ ] El build no debe necesitar credenciales reales: si falta una variable, usar valores ficticios definidos en el workflow (no secretos). Si más adelante Prisma necesita generar el cliente, agregar `pnpm prisma generate` antes del build.
- [ ] `concurrency` para cancelar ejecuciones viejas del mismo PR.
- [ ] `.github/pull_request_template.md` con: step que cierra (enlace), qué cambia, cómo probarlo y checklist (lint, tests, notas del step completadas, fila del índice actualizada).
- [ ] Documentar en el README que el check "CI" es obligatorio, y pedir a quien administra el repo que lo marque como requerido en la protección de `main`.

## Criterios de aceptación

- Un PR con un error de tipos o un test roto muestra el check en rojo y no se puede mergear.
- Un PR correcto muestra el check en verde en menos de 5 minutos.

## Fuera de alcance

- Tests E2E. Deploy (lo hace Vercel).
