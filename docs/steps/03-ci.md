# Step 03 — CI con GitHub Actions

**Etapa:** 1. Base · **Depende de:** 01 · **Leer:** `AGENTS.md` sección "Git y PR"

## Objetivo

Que cada PR ejecute automáticamente lint, chequeo de tipos, tests y build, y que no se pueda mergear si algo falla.

## Tareas

- [x] `.github/workflows/ci.yml` que corra en `pull_request` hacia `main` y en `push` a `main`.
- [x] Pasos: checkout, `pnpm/action-setup`, `actions/setup-node` con la versión de `.nvmrc` y caché de pnpm, `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`.
- [x] El build no debe necesitar credenciales reales: si falta una variable, usar valores ficticios definidos en el workflow (no secretos). Si más adelante Prisma necesita generar el cliente, agregar `pnpm prisma generate` antes del build.
- [x] `concurrency` para cancelar ejecuciones viejas del mismo PR.
- [x] `.github/pull_request_template.md` con: step que cierra (enlace), qué cambia, cómo probarlo y checklist (lint, tests, notas del step completadas, fila del índice actualizada).
- [x] Documentar en el README que el check "CI" es obligatorio, y pedir a quien administra el repo que lo marque como requerido en la protección de `main`.

## Criterios de aceptación

- Un PR con un error de tipos o un test roto muestra el check en rojo y no se puede mergear.
- Un PR correcto muestra el check en verde en menos de 5 minutos.

## Fuera de alcance

- Tests E2E. Deploy (lo hace Vercel).

## Notas de implementación

- **Qué se hizo:** Se agregó el workflow de CI en GitHub Actions con `pull_request` a `main` y `push` a `main`, usando `pnpm/action-setup`, `actions/setup-node` con `.nvmrc` y caché de pnpm, instalando con `pnpm install --frozen-lockfile`. Se ejecutan `lint`, `typecheck`, `test` y `build`, con `concurrency` para cancelar ejecuciones viejas. Se añadieron variables dummy para evitar requerir credenciales reales en el build, con intento opcional de `pnpm prisma generate`. Se creó `.github/pull_request_template.md` con checklist y se documentó en `README.md` que el check "CI" debe marcarse como requerido en la protección de `main`.
- **Archivos clave:** `.github/workflows/ci.yml`, `.github/pull_request_template.md`, `README.md`
- **Decisiones:** Usar valores ficticios en el job (no secretos) para que el build funcione sin configurar credenciales; mantener `prisma generate` opcional (`|| true`) hasta que exista `schema.prisma`. Se documenta la obligatoriedad del check en README sin intentar modificar protección remota desde el repo.
- **Desvíos del spec:** Ninguno.
- **Cómo probarlo:** Abrir un PR hacia `main` con un cambio válido → el workflow "CI" debe correr y pasar (lint, typecheck, test, build). Introducir un error de tipos o test roto → debe fallar y bloquear merge.
- **Pendientes:** Ninguno.
